# 文档类型路由与字段地图

## 路由表

| 文档特征 | 类型 | 关键产出 |
|---|---|---|
| 出现雇主/承包商等当事人、索赔、EOT、裁决、意见书、函件编号 | 争议/法律程序文书 | 争议矩阵 + 观点分级 |
| 摘要/引言/方法/实验/讨论/参考文献结构，有基线与消融 | 学术论文 | 论点-证据矩阵 + scorecard |
| 执行摘要/发现/建议结构，有财务或运营数据、利益相关方 | 商业/技术报告 | 发现×证据强度×影响矩阵 |
| 条款/办法/征求意见结构，有"应当/鼓励"效力差 | 政策/规章/咨询 | 条款×受影响方×生效状态 |

## 类型 1：争议/法律程序文书（实战最深）

**触发特征**：标题含 report/decision/recommendation/advisory；出现 NoD、EOT、Variation、claim 等术语；大量函件交叉引用；作者署名带职位（DRAd/DAB/裁决员/律师/QS）。

**典型功能块**（依此切分，勿按页）：程序史 → 争议标的（NoD 内容+提问清单+救济请求）→ 作者自我限定（审什么、不审什么）→ 条款与判例铺垫 → 逐项争议分析 → 方法论 → 关键分歧/障碍 → Way Forward。

**实体矩阵列定义**（核心交付物）：
`争议点 | 各方主张与依据（分列） | 关键合同条款 | 关键判例 | 裁决者/顾问初步看法（带分级） | 待办（谁需补什么）`

**五大失焦陷阱与对策**：
1. **准司法性对冲**——advisor/调解角色通篇 "seems/perceptions"。对策：全部落【倾】，结论区声明"非裁决、仅促进和解"。
2. **结论后置**——实质观点常在正文 2/3 之后，前面是条款判例铺垫。对策：Phase 1 先定位结论区，骨架围绕它组织。
3. **多方立场缠绕**——两方以上主张+往来函件引用。对策：矩阵分列各方、函件号挂靠；绝不合并转述成"双方都有道理"式的和稀泥。
4. **关联文件网**——引用既往报告/NoD/信函。对策：L4 时输出关联文件地图（文件号、日期、状态、与本案关系）；单文件模式至少列出"被引用而未随附"的文件清单。
5. **entitlement 与 quantum 分离**——程序上常分阶段处理。对策：明确声明本文件处理到哪一层、哪一层被明确搁置。

**硬信息底账（必录清单）**：索赔金额及构成、关键天数（delay days）、关键日期线、阈值/比例、当事方与顾问全名、合同编号。

## 类型 2：学术论文/研究报告

**字段地图**：问题 → 方法 → 证据 → 局限 → scorecard（是否值得精读/复现/引用）。

**实体矩阵**：`核心主张 | 支撑证据（Table/Fig 编号）| 证据强度（基线/消融/显著性）| 边界与反例 | 分级`。

**陷阱与对策**：①复述摘要当总结——摘要只写"做了什么"，总结要回答"证明了什么、没证明什么"；②报结果不给基线——落【定】前检查有无对照；③novelty 声明照抄——与相关工作章节对照实际 delta，够不上就落【主】并注明；④讨论中的推测混入发现——推测落【倾】并注明在 Discussion 而非 Results。

## 类型 3：商业/技术报告（尽调/中期评估/可研/审计）

**字段地图**：评估对象与范围 → 发现（×证据强度×影响）→ 各方意见 → 建议（×前提条件）→ 待办。

**实体矩阵**：`发现 | 证据与出处（审计/访谈/文件审阅/实测）| 证据强度 | 被评估方回应 | 评估方处理`。

**陷阱与对策**：①建议不带前提——"建议加速"必须保留"在什么条件下"；②警示与例外埋在脚注/附录——底账里必须收录；③未审计数据与审计数据混排——未审计落【主】；④被评估方回应被吸收成事实——回应单列，不合并。

## 类型 4：政策/规章/咨询文件

**字段地图**：文件性质（试行/正式/征求意见稿）→ 条款结构 → 义务/倡导区分 → 受影响方 → 过渡安排 → 开放征求意见项。

**实体矩阵**：`条款群 | 效力词（应当/必须/鼓励/倡导——原样保留）| 受影响方 | 主要反馈/争议 | 实施依赖`。

**陷阱与对策**：①把"鼓励"读成"应当"；②把征求意见稿当已生效——文件状态写进结论区；③义务-罚则-救济的对应关系丢失——对应表保留。

## 混合类型

按**主要功能**路由（谁要读、读来做什么决定主类型），可叠加其他类型的字段：如"争议报告附有评估章节" = 类型 1 为主 + 类型 3 的证据强度字段。
